# ayrup — клікабельний прототип

Гра-симулятор готовності проєкту. Пілот реєструється й створює рейс, екіпаж приєднується за посиланням, кожен окремо проходить ситуації, а наприкінці команда отримує:

- відсоток готовності;
- узгодженість екіпажу;
- карту компетенцій;
- маршрут фінансування.

У грі 8 систем і 35 ситуацій. Набір ситуацій залежить від профілю фінансування:

| Профіль | Ситуацій |
| --- | --- |
| А — грант уже є | 32 |
| Б — подаємось на грант | 22 |
| В — ще не знаємо | 25 |
| Г — власним коштом | 20 |

## Два режими

**Демо-режим** вмикається сам, поки `config.js` порожній. Усе зберігається лише в браузері. Цей режим зручний, щоб самому подивитися гру. Кнопка «Додати тестовий екіпаж» імітує команду.

**Робочий режим** з базою Supabase потрібен для тесту зі знайомими. Ліди, рейси й відповіді зберігаються на сервері, а екіпаж грає зі своїх пристроїв.

## Запуск за 15 хвилин

### 1. База даних (Supabase, безкоштовний план)

1. Створіть проєкт на supabase.com. Для Німеччини оберіть регіон **Frankfurt (eu-central-1)**: дані лишаються в ЄС.
2. Відкрийте **SQL Editor → New query**, вставте вміст `supabase/schema.sql` і натисніть **Run**.
3. Скопіюйте **Project URL** (кнопка **Connect** угорі або **Project Settings → Data API**) та **Publishable key** (`sb_publishable_…`) з **Project Settings → API Keys**. Старий ключ `anon` теж підійде.
4. Вставте їх у `config.js`.

Publishable key можна тримати в публічному коді. Таблиці закриті, а сторінка працює з базою лише через функції, які перевіряють секретні токени учасників.

### 2. Публікація (GitHub Pages)

1. Створіть репозиторій на GitHub, наприклад `ayrup-prototype`.
2. Завантажте в нього всі файли цієї папки, разом із `.nojekyll`.
3. Відкрийте **Settings → Pages → Build and deployment**, у полі **Source** оберіть **Deploy from a branch**, далі гілку `main` і папку `/ (root)`.
4. За хвилину сайт буде доступний на `https://<ваш-логін>.github.io/ayrup-prototype/`.

Посилання для екіпажу мають вигляд `…/#join-<id>`. Пілот копіює його на сторінці рейсу.

## Де дивитися ліди

- Supabase → **Table Editor → leads**: усі пілоти й учасники екіпажу, з позначкою, хто попросив консультацію (`wants_expert`).
- Зведена таблиця з проєктом і профілем: у **SQL Editor** виконайте `select * from leads_export order by created_at desc;` і натисніть **Download CSV**.

## Як змінювати ситуації

Тексти ситуацій лежать у `src/data.py`. Після змін виконайте:

```
python3 src/data.py
python3 src/build.py
```

Друга команда перезбирає `index.html`.

## Перед публічним запуском

Для тесту зі знайомими цього достатньо. Для відкритого запуску в Німеччині ще треба:

- **Сторінки Impressum і Datenschutzerklärung.** Додайте їх і посилання на них у футері.
- **Договір про обробку даних із Supabase (DPA).** Його можна укласти в їхніх налаштуваннях.
- **Вхід за посиланням на пошту.** Зараз вхід працює без пароля: сесія пілота зберігається в браузері. Для стабільнішого входу можна підключити Supabase Auth (magic link).
- **Перевірка правил.** Кожну грантову ситуацію має перевірити експерт: правила відрізняються між програмами й землями.
